# 社区独居老人一键求助 · 上门核实转介回访平台

面向社区独居老人照护场景：老人通过**智能按钮、电话、社区小程序**发起求助后，值班社工在同一条事件中完成
**求助受理 → 研判分类 → 分级转介 → 上门核实 → 后续服务 → 家属沟通 → 回访归档**，
并在归档时联动更新老人照护画像、家属响应表现、邻里协助可信度与下一次主动关怀计划，
支撑社区管理者按风险等级、响应时长、服务类型、回访结果复盘独居老人照护能力。

针对**老人拒绝就医**场景，平台提供风险随访闭环：登记医生建议、老人拒绝原因、家属知情与态度、
替代照护安排后，事件不能直接归档，自动生成 24 小时内复访任务（电话复访 / 上门复访 / 医生复诊）；
复访发现症状加重时自动提升风险等级并重新通知家属和家庭医生；症状未缓解的拒医记录会随老人
下一次求助自动带入新事件，防止值班人员只看到一次新的普通求助。

## 技术栈

- 前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts（SSE 实时告警）
- 后端：Spring Boot 3.3 + Spring Data JPA + Redis（登录令牌）+ PostgreSQL
- 基础设施：Docker Compose 一键启动 postgres / redis / backend / frontend

## 一、Docker 一键启动（推荐）

前置：安装 Docker 与 Docker Compose。

```bash
cd 170-b
docker compose up -d --build
```

启动后访问：

| 服务 | 地址 |
| --- | --- |
| 前端页面 | http://localhost:8081 |
| 后端 API | http://localhost:8080/api |

首次启动自动建表并写入 5 个测试账号和 3 位示例老人档案（周桂兰、吴德海、郑秀珍）。

停止与清理：

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并清空数据库/上传文件
```

## 业务功能与验证路径

### 1. 一条事件贯通全流程（“求助—核实—上门—转介—服务—家属沟通—回访”）

值班工作台 →「模拟一键求助」选择老人与来源（智能按钮/电话/小程序），填写语音内容与定位 →
进入事件详情，依次操作：

1. **值班研判**：生活协助 / 身体不适 / 跌倒风险 / 情绪危机 / 误触，严重程度 低/中/高/紧急；
2. **转介通知**：按严重程度通知网格员 / 邻里志愿者 / 家庭医生 / 120，可登记邻居代报及信息是否清晰，并更新受理/到场状态；
3. **上门核实**：入户方式（钥匙、门禁密码、智能锁授权、邻居/家属开门、破锁、未能入户）、现场照片上传、
   老人状态、是否联系家属、是否需要送医、是否拒绝就医、是否需要临时照护、后续服务建议、家中安全隐患；
4. **家属沟通**：多次拨打接通情况与态度（连续未接通自动判定“家属长期不接电话”）；
5. **后续服务**：临时照护、送医陪诊、日常巡访、助餐、适老化改造、心理陪伴；
6. **回访归档**：好转/平稳/恶化/未联系上 + 满意度 + 下一次主动关怀计划，归档联动更新画像。

右侧固定展示**老人照护画像**（长期独居、燃气报警器、最近家属探访、医生随访结论、历史误触、
基础病、门禁信息、紧急联系人、邻里响应人），底部为全过程时间线留痕。

### 2. 七类特殊风险自动/手动标记，全程沉淀在同一事件

| 风险 | 触发方式 |
| --- | --- |
| 无法开门 | 上门记录“未能入户”或入户方式为未能入户 |
| 定位偏移 | 求助坐标与档案住址距离 > 500 米自动判定（阈值可配） |
| 家属长期不接电话 | 档案联系人已标记，或同一事件累计 ≥2 次未接通 / 联系人累计未接通率超 2/3 |
| 邻居代报信息不清 | 转介时勾选“邻居代报·信息不清”，同时下调该邻里可信度 |
| 老人拒绝就医 | 上门记录勾选 |
| 家中存在安全隐患 | 上门填写隐患描述（自动建议适老化改造） |
| 频繁夜间求助 | 22:00–06:00 求助，近 30 天夜间求助 ≥3 次自动标记（阈值可配） |

### 3. 拒绝就医后的风险随访（24 小时复访闭环）

1. **拒医登记**：家庭医生判断老人身体异常（如血压 182/110）建议就医但老人拒绝时，
   在事件详情点击「拒医登记」，记录**医生建议、异常发现、老人拒绝原因、家属是否知情与态度、
   替代照护安排**，并选择首轮复访方式（电话复访 / 上门复访 / 医生复诊）；
2. **事件不能直接关闭**：登记后自动生成 **24 小时内复访任务**，事件存在随访中的拒医记录时
   「回访归档」被禁用，后端同样拦截并提示先完成复访；
3. **复访任务**：值班工作台顶部展示待复访任务（老人、事件、方式、医生建议、截止时间，逾期红色标记），
   三种复访方式可并行追加；复访结果分 症状缓解 / 未缓解 / 症状加重 / 未联系上；
4. **症状加重**：自动将拒医记录、事件严重程度、老人画像风险等级各提升一档，
   **重新通知家属（平台推送主要紧急联系人）和家庭医生（自动转介）**，SSE 实时告警值班人员，
   并生成下一轮 24 小时复访任务（默认升级为上门复访）；
5. **症状未缓解**：拒医记录保持随访中并生成下一轮复访；老人再次求助时，
   **原拒医记录、家属态度、医生建议自动带入新事件**（风险标记 + 时间线提示 + 详情页顶部红色警示），
   防止值班人员只看到一次新的普通求助；
6. **症状缓解**：拒医随访解除，事件方可正常回访归档。

### 4. 事件不停在处置结果——归档联动更新

回访归档后系统自动：

- 重算老人**综合风险等级**；
- 更新**家属响应表现评分**（本事件接通率）与联系人接通统计；
- 更新**邻里协助可信度**（有效响应、代报信息质量）；
- 累加**误触记录**；
- 依据跌倒/隐患/情绪危机/临时照护等勾选**增加日常巡访、助餐、适老化改造、心理陪伴**建议；
- 生成**下一次主动关怀计划**（可手动指定，否则按严重程度 1/3/7/14 天自动排期）。

### 5. 社区管理者复盘

「照护能力复盘」页（admin 账号可看全部数据）支持按时间区间统计：
事件总数/夜间/送医、按风险等级分布、按研判类型分布、按服务类型分布、按回访结果分布、
每日求助趋势、平均/最快/最慢响应时长与 15 分钟到场率、七类风险场景出现频次。

## 已执行的验证（本地实际验证结论）

### 拒绝就医风险随访（2026-10-06，JDK 17 + Maven 3.8 + Node 22 + PostgreSQL 15 + Redis 7）

1. **后端编译打包**：`mvn package -DskipTests` 成功，产出 `target/eldercare.jar`。
2. **拒医登记 → 24 小时复访任务**（curl，worker 账号）：周桂兰电话求助 → 研判（身体不适/高）→
   转介家庭医生 → 上门（需送医 + 拒绝就医）→ 登记拒医（血压 182/110、建议急诊、老人害怕住院、
   家属知情但推诿、居家测压替代照护）→ 自动生成 **24 小时电话复访任务**（截止时间为登记后 24 小时）。
3. **归档拦截**：拒医随访未解除时调用回访归档返回 400「存在未解除的拒绝就医风险随访…」。
4. **复访症状加重**：完成复访选「症状加重」→ 事件严重程度 高→紧急、老人画像风险 高→极高、
   拒医风险等级同步提升；系统**自动重新通知**（生成家庭医生的转介通知 + 主要紧急联系人的平台推送，
   操作人均为“系统”），并自动生成下一轮 24 小时**上门复访**任务；SSE 实时推送 `refusal-escalated`。
5. **复访未缓解**：拒医记录保持随访中并生成下一轮电话复访任务。
6. **新求助带入历史**：同一老人再次发起求助，新事件自动带 `REFUSE_HOSPITAL` 风险标记，
   时间线写入“历史拒医带入”日志（含原拒医记录、家属态度、医生建议、替代照护），
   详情接口返回 `activeRefusal` 供页面顶部红色警示；拒医解除后新事件不再带入。
7. **复访缓解 → 归档**：复访选「症状缓解」→ 拒医记录解除、其余待复访任务自动取消，
   事件可正常回访归档（状态 CLOSED）。
8. **边界校验**：重复登记拒医 400、重复追加同方式任务 400、非法复访方式 400、
   缺医生建议/拒绝原因 400 参数校验。
9. **前端**：`npm run build` 构建成功；Vite dev（5173）启动后经代理登录 worker 成功，
   待复访任务接口经前端代理正常返回。
